## Evidence

- **Changed selected transitive helper cannot receive a new report in the reused runtime instance.** `packages/contract-registry/src/assurance-runtime.ts:26–35` hashes the complete absolute-path/digest inventory and rejects a different inventory for an overlapping canonical root. `:41–48` canonicalizes and retains the root, copies the input map, verifies selected bytes, and reserves before importing. Thus the second helper-2 invocation cannot reach its target import or return a bundle under helper-2 hashes after helper-1 was loaded. The exact two-run regression is in `tests/assurance/runtime-cache.test.ts:30–34`. The recorded built-package native run independently reports unchanged outputs `[1,1]`, reused-process refusal after helper change, and fresh-process output `2`; the native Node characterization explains why the original target nonce was insufficient.
- **Canonical aliases and overlapping roots are covered without changing equivalent inventory semantics.** Runtime `:25–35` uses path-component containment in both directions and keys inventory by `join(canonicalRoot, relativePath)`, so equivalent root/nested-root spellings produce the same identity. `hash` canonicalizes object keys (`packages/core/src/serialization.ts:2–34`), making insertion order immaterial. Existing `safeRead` rejects symlink components below the root (`packages/core/src/io.ts:7–23`), supporting the physical-path interpretation. Alias/nested-root tests demonstrate unchanged reuse and changed-helper refusal (`runtime-cache.test.ts:35–51`); addition/removal tests cover inventory changes (`:52–57`). Refusing even unrelated selected-file changes within overlapping roots is the documented intentional conservatism.
- **Concurrency and failed attempts do not reopen the original hole.** Reservation checks and publication contain no await (`assurance-runtime.ts:26–35`) and occur before the awaited read/import (`:47–48`). Equivalent overlapping snapshots share the same taint object. An exception after reservation taints it permanently (`:193`), and an in-flight run rechecks that state immediately before returning (`:190–192`). Partial imports and mutation-then-restoration therefore cannot be retried as a clean snapshot. If `reserveSnapshot` itself rejects a conflicting inventory, the caller has not assigned `snapshot`, so its catch does not poison the valid original inventory. The concurrent test also awaits the original run successfully after refusing the conflict (`runtime-cache.test.ts:64–75`); failed-mutation and partial-import tests are at `:58–63` and `:76–81`.
- **Unchanged API reuse and closures remain supported.** Same-root/same-identity reservation returns the prior snapshot (`assurance-runtime.ts:34`); the caller's driver still executes directly via `withContext` (`:117–120`). The regression test deliberately retains a driver closure and observes outputs `1` then `2` (`runtime-cache.test.ts:25–29`). Architecture-only collection returns through `inspectArchitecture` before executable `load` (`assurance-runtime.ts:84`), so it does not acquire the cache reservation.
- **Documentation matches the implemented scope.** `docs/assurance.ja.md:91–93` explains unchanged selected inventories, aliases/overlap, permanent refusal after a reserved execution throws, architecture-only behavior, closures, and exclusions from full dependency isolation. The fresh-process CLI recommendation is supported by its existing `execFile(process.execPath, [worker, ...])` for each execution (`packages/cli/src/assurance-command.ts:22–27`).

## Limits

This review does not establish universal JavaScript cache isolation. Protection depends on the selected input inventory and the single loaded runtime module instance. Preloaded code, undeclared dependencies, external modules shared across disjoint roots, mutable module state, duplicate runtime instances, and transient mutation between checks remain outside the guarantee, as the implementation report states. Reservations intentionally persist for process lifetime and can refuse recoverable failures or harmless inventory changes. These are consistent with the requested supported strategy, not newly discovered regressions.

The reported focused result is 49 passing tests across the runtime/cache files after allowing loopback access, with TypeScript build and diff whitespace checks passing. Those are reviewed recorded results, not independent reruns; final full-suite status is left to the root agent.
