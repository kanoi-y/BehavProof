# Repository boundaries

The canonical public project is [kanoi-y/BehavProof](https://github.com/kanoi-y/BehavProof). Product packages, CLI, tests, examples, templates, documentation and three-platform product CI live at this repository's root. Its initial public history is a reviewed source snapshot; private local development history, source specifications, execution plans, credentials and working logs are not published. They remain local.

[pdd-ts](https://github.com/kanoi-y/pdd-ts) is a separate application used to evaluate BehavProof's value and behavior. It must not contain a vendored BehavProof implementation. Consumer workflows explicitly check out `kanoi-y/BehavProof` at a full protected `BEHAVPROOF_SDK_SHA`, build it in `sdk/`, and pass only the separately staged public SDK to isolated candidate execution. Workflow authority and credentials remain separately protected in the consumer repository.

`node scripts/prepare-validation.mjs --sdk-sha <public-BehavProof-commit> --output <directory>` prepares only two consumer workflow files and the small `validation/behavproof-probe/` verification fixture. It never copies product packages/tests/root CI or opens/merges a PR. The fixture is a controlled enforcement check, not evidence of value on the actual PDD implementation; real PDD behavior/quality evaluation remains separately required.

Earlier pdd-ts PRs [7](https://github.com/kanoi-y/pdd-ts/pull/7) and [8](https://github.com/kanoi-y/pdd-ts/pull/8) copied product source under `validation/behavproof-m2/`. They were closed without merging when this boundary was clarified. Historical branches, reviews and run hashes remain as audit evidence; they are not the product source of truth. Historical evidence files retain their original repository and commit identities. The old PR8 main-deployment approval request is superseded and must not be acted on.

Product CI runs in BehavProof. Future pdd-ts changes are limited to application-specific contracts/configuration and thin integration, with separate human review and protected provisioning when required. Closing the copied-source PRs does not establish live protected-check acceptance: M2's outstanding external tests remain outstanding.
