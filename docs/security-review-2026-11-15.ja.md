# 初回配布前セキュリティ点検（2026-11-15）

対象はBehavProof SDKとnpm初回配布経路。外部侵入テストやプログラム全体の安全性証明ではない。npm公開・限定アクセスの実地確認は、公開方式とスコープが確定してから別途記録する。

## 発見と改善

| 項目 | 確認した問題 | 改善・検証 |
|---|---|---|
| GitHub APIのリポジトリ境界 | `%2e%2e` がURL正規化で指定リポジトリ外へ解決され、パス文字列の検査を通過した | 認証ヘッダーを付ける前にURL正規化結果を照合。エンコードされた親参照・バックスラッシュ・fragmentを拒否。回帰テストと既存通信・authority・publisher計70テスト通過 |
| npm送信先 | `--registry` だけでは、ユーザーの `@behavproof:registry` 設定が優先される | グローバル・スコープ別双方を公式registryへ固定。悪意あるuserconfigを実際のnpm CLIに渡す回帰テスト通過 |
| 初回公開の2FA | 非対話stdioではnpmのOTP対話が利用できない | 公開プロセスのみ管理者端末のstdioを継承。失敗時は自動で公開範囲を変えず、対話端末での再実行を案内 |
| 壊れた配布物 | package.jsonのみのtarballでも、構造上は正しいためハッシュ検査だけを通過できる | exports／types／bin等の実ファイルとCLI必須アセットを確認。欠落の回帰テスト通過 |
| 配布物の差し替え | 転送元ディレクトリを後から更新すると、確認済みbytesと公開時のbytesがずれ得る | 検証済みtarballを管理者のprivate一時領域へスナップショットし、公開前にSHA-512再確認 |

## その他の確認

- ビルド通過。最終の全自動テストは46ファイル・400件通過（`vitest run --maxWorkers=1 --testTimeout=30000`）。並列の梱包・インストール負荷下で既存CLI／formal fixtureの時間制限が作動したため、他の検証終了後に直列で全件確認した。製品のタイムアウト設定やassertionは緩めていない。

- `npm audit` と `npm audit --omit=dev`：既知の脆弱性0件（この日時・依存ロックに限定）。
- Git管理対象ファイルの秘密鍵・GitHub/npmトークン・AWSアクセスキー形式の走査：検出0件。未知形式の秘密情報や意図的な偽装まで保証するものではない。
- 実際の8tarballについて、内容一覧、通常ファイルのみ、パス、重複、サイズ、tarチェックサム、秘密情報形式、metadata、内部依存バージョン、entrypointを検査し通過。
- 全8パッケージを別ディレクトリにonlineインストールし、公開API、CLI、スキーマ、formalツールが必須導入されないことを確認（`node scripts/package-smoke.mjs --online --formal`）。
- 独立レビューのImportant指摘3件は修正・再レビュー済み。Critical・Importantの残件なし（確認した範囲に限定）。

- GitHubの非公開脆弱性報告を有効化し、`.github/SECURITY.md` に機密情報をpublic Issueへ載せず報告する経路を追加。

## 継続して必要な運用

候補コードの実行と公開資格情報を分離する。Collector・明示的なモデルDriver／ツールはコードを実行するため、隔離・ネットワーク制限・資格情報なしのworkerで実行する。JSON、テスト成功、同名Checkだけを承認根拠にしない。検証器の固定コミット、保護されたワークフロー、必須CheckのApp ID、現在HEADへの人間レビューを維持する。

公開スコープの所有権と配布権限、全パッケージのアクセス状態、registryからのインストール、正確なソースコミットとタグの対応は、Release完了前に実地確認する。npm限定公開であってもpublic GitHubソースの閲覧や利用者の再配布を防ぐものではない。
